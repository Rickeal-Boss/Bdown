# 真机验证清单（v1.4.14）

> 为什么要这份清单：v1.4.7 ~ v1.4.14 一天内发布了 8 个版本，CI 20 个套件全绿，
> 但**一次真机验证都没做**。而今天修的两个最严重的问题（merge 崩溃、360P）
> 恰恰都是 **CI 测不到的路径**：
> - merge 崩溃：只有文件 > 256MB 才会走 OPFS `FileHandleSink`，而 CI 用的是几 KB 合成片段
> - 360P：`buildPlan` / `try_look` 的行为依赖真实账号权限，CI 是未登录沙箱
>
> **CI 绿 ≠ 能用。这份清单是上架前的门槛。**

## 前置

1. 加载 `dist/Bdown-v1.4.14.zip`（或用 `node tools/package.mjs` 重新打包）
2. `chrome://extensions` → 点「重新加载」
3. 打开 DevTools Console（后续失败时要复制里面的内容）
4. **登录 B 站**——清晰度相关的验证必须登录

---

## A 组｜P0：不做完不能上架

### A1. 大文件 merge（最关键）

| 步骤 | 期望 |
|---|---|
| 找一个 **>10 分钟、1080P** 的视频（确保视频轨 > 256MB，才会走 OPFS 路径） | — |
| 视频页 → 点悬浮「下载」→ 下载方式保持默认 **合并为 MP4** → 开始 | 进度正常走完，状态变「已完成」 |
| 打开产物 | **能播放、音画同步、时长正确** |

**这是 v1.4.7 修的那个 bug 的验证点。** 修复前这里会报
`无法合并：在文件头部未找到 moov`，且发生在音视频都下完之后。

**若失败，请复制**：完整报错 + Console 里 `已扫描到的顶层 box：...` 那一行。
- 显示 `（空）` → 文件是空的，说明 sink 数据没落盘（flush 问题复发）
- 显示 `ftyp,moov,...` 却仍失败 → 是 mp4.js 的解析问题，与本次修复无关

### A2. 清晰度（已登录非会员）

| 步骤 | 期望 |
|---|---|
| 打开一个**有多档清晰度**的视频 → 弹窗 | 清晰度列表只把**真实存在**的档位标为可选 |
| 不选、直接下载 | 拿到该账号权限内的**最高档**（不应是 360P） |
| 手动选 1080P | 拿到 1080P；若不可得，应降到**最接近**的档而不是最低档 |

修复前的三个病（v1.4.8 修）：
1. `buildPlan` 会静默降到 `accept` 末位（最低档）
2. 登录态未知时误发 `try_look=1`，拿到未登录试看流
3. `pickVideoTrack` 只看码率，低清码率高就被选中

**若仍是 360P**：看 Console 是否有 `请求的清晰度不可用，已就近调整 请求 X → 实际 Y`。

### A3. 大会员档位（若你有大会员）

登录后打开支持 4K/1080P+ 的视频，确认能选到并真的下到对应档位。

## B 组｜本轮新功能

### B1. NFO（选项页 → 勾选「保存 NFO 元数据」）

| 步骤 | 期望 |
|---|---|
| 用 **merge** 模式下一个视频 | 目录里多出 `同名.nfo` |
| 用文本编辑器打开 | 是合法 XML，有 `<title>` / `<plot>` / `<runtime>` |
| 丢进 Jellyfin 媒体库 | 能被刮削出条目（**关键**：若静默丢弃，说明 XML 有问题） |
| 切到 **音视频分离** 模式再下一次 | **不产生** NFO（这是刻意设计：两个产物都不完整） |

注意 `<runtime>` 不应出现 `0`（v1.4.13 修）。

### B2. 合集批量（v1.4.14 新增）

| 步骤 | 期望 |
|---|---|
| 打开一个**属于合集**的视频（如 BV1Wi4y1k7ed，7 集） | 弹窗出现「所属合集」区块，显示《合集名》与集数 |
| 勾选「下载整个合集」 | 底部「共 N 个任务」变成合集集数 |
| 开始下载 | 逐集建立任务并下载 |

**注意**：不是每个视频都有合集——没有时该区块不显示，这是正常的。

### B3. 章节（选项页 → 勾选「保存章节」）

找一个**进度条上有分段标记**的视频下载，应产出 `chapters.txt`（或 `.vtt`）。
若没有产出，可能是该视频确实无章节——**这一项的 `view_points` 真实字段结构尚未真机确认**。

## C 组｜稳定性与回归

| # | 操作 | 期望 |
|---|---|---|
| C1 | 下载中在下载中心点「取消」 | 状态变「已取消」，**不残留半截文件**；关掉下载中心再打开，该任务**不再出现** |
| C2 | 失败后点「重试」 | 进度/速率/完成时间都归零，不显示上一轮的数据 |
| C3 | 断网 → 下载失败 → 恢复网络 → 重试 | 能完整下完（v1.4.6 的 URL 过期刷新会重新 playurl） |
| C4 | 解析后**等 2 小时以上**再点下载 | 地址过期也能自动刷新重试（Console 会有「播放地址疑似过期」） |
| C5 | 连续点两次「开始」 | 不会起两个重复任务 |
| C6 | 多P视频勾选 P1/P2 | 出 2 个文件，文件名按模板带 `_P01_` |

## 失败时请给我这些信息

1. **完整报错文本**（下载中心的任务行 + Console）
2. Console 里所有 `[Bdown]` 开头的行
3. 复现步骤（哪个 BV 号、什么清晰度、什么下载模式）
4. 浏览器与版本（Chrome / Edge + 版本号）

## 已知未验证项（不要当成"已支持"）

- 章节的 `view_points` 真实字段结构（B站未公开文档，兼容了三种写法）
- 课程（pugv）：接口需登录且多为付费内容，**从未真机验证**
- 番剧/课程的 NFO episode 形态：同上
- 合集批量只验证过**解析逻辑**（44 项 CI 测试），弹窗 UI 部分未真机验证
