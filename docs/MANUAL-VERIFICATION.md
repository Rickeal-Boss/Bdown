# 真机验证清单（v1.4.21）

> 为什么要这份清单：多个版本一天内连发，CI 全绿，但**真机验证才是门槛**。
> v1.4.20/v1.4.21 修的问题，恰恰都是 **CI 测不到的路径**：
> - **主页面登录被破坏**：DNR 规则副作用，只在真实浏览器 + 真实 B 站页面才会显现
> - **弹窗谎报可用档位**：需要真实接口响应（`accept_quality` 虚报）才暴露
> - **Referer 从未送达**：fetch 层设不了 forbidden header，只在真实浏览器暴露
>
> **CI 绿 ≠ 能用。**

## 前置

1. 加载 `dist/Bdown-v1.4.21.zip`（或用 `node tools/package.mjs` 重新打包）
2. `chrome://extensions` → **务必点「重新加载」**（DNR 规则改动必须重载才生效）
3. 打开 DevTools Console（后续失败时要复制里面的内容）
4. **登录 B 站**——清晰度相关的验证必须登录

---

## ★ 组｜v1.4.21 专项（本轮最关键，请优先做）

### ★1. 主页面登录不再被扩展破坏（P0）

**背景**：旧版扩展开着时，`message.bilibili.com` / `t.bilibili.com` /
`space.bilibili.com/<uid>/favlist` / `member.bilibili.com/platform/upload/video/frame`
这些页面登录不了。真因是 DNR 规则无差别改/删了这些子域请求的 `Origin` 头
（连 `passport.bilibili.com` 登录接口都被命中）。

| 步骤 | 期望 |
|---|---|
| **保持扩展启用**，依次打开上面 4 个页面 | 全部能正常显示登录态（头像/昵称/收藏夹内容） |
| 若当前未登录：在扩展启用状态下走一次登录流程 | **能登录成功**，不被拦 |
| `chrome://extensions` → 详情 → 查看「错误」 | 无 DNR 规则语法错误 |

**若仍失败**：DevTools Network 里看失败请求是否报 `blocked by CORS policy`。
若有，复制该请求的 `Origin` / `Access-Control-Allow-Origin` 头给我。

### ★2. 弹窗显示的清晰度 = 实际下载的清晰度（P0，本轮核心）

**背景**：旧版弹窗用 `pickVideoTrack` 判断"这一档能不能下"，而它会**回退到低档并返回
非空轨道**，于是 `available` 恒为真 —— 弹窗把 1080P60 标成"可用"，实际只有 480P。
用户选了"1080P60"，下来是 360P。**这很可能就是你一直看到的那个现象。**

| 步骤 | 期望 |
|---|---|
| 打开一个**有多种清晰度**的视频 → 弹窗 | 只有**真实存在**的档位显示可用；不存在的档位显示「不可用」 |
| 直接点「开始下载」 | 下载到的清晰度 = 弹窗里高亮的那个档位 |
| 打开下载中心 → Console 找 `清晰度诊断` | `picked` 应与弹窗显示一致 |

**`清晰度诊断` 判读表**（v1.4.21 新增 `isLogin` / `vip`）：

| 日志表现 | 含义 | 处理 |
|---|---|---|
| `picked` 与弹窗显示一致 | ✅ 正常 | 通过 |
| `isLogin=false` | Cookie 未送达 / 未登录 | 把整行发我（按实测此路基本排除） |
| `isLogin=true` 但 `dashVideos` 最大只有 16/32 | 服务端没按登录态给高画质 | 把整行发我 |
| `isLogin=true` 且 `dashVideos` 含 80/112，`picked` 更低 | 客户端选轨 bug（未修净） | 把整行发我 |
| `accept_quality` 有 80 但 `dashVideos` 没有 | 账号权限 / 内容限制 | 换个视频复验 |

**另测**：设置页把「默认清晰度」改成 `80 · 1080P 高清` → 保存 → 关闭再打开设置页 →
**应仍是 1080P**（旧版会被 popup 静默重置成"自动"）；再打开弹窗，应**默认选中 1080P**
（v1.4.21 之前弹窗完全无视这个设置）。

### ★3. 扩展自身功能未被 DNR 收窄影响（回归）

DNR 规则 3/4 加了 `excludedInitiatorDomains: ["bilibili.com"]` —— 只对扩展自身
（`chrome-extension://` 来源）生效。需要确认扩展自己的请求**仍然能绕开 WAF**：

| 步骤 | 期望 |
|---|---|
| 打开视频页 → 弹窗能正常解析出标题/封面/清晰度列表 | 说明 `api.bilibili.com` 请求未被 412 拦 |
| 完整下载一个视频（含弹幕） | 成功；弹幕文件也生成（说明 `comment.bilibili.com` 正常） |

## B 组｜历史新功能回归（可选）

### B1. NFO（选项页 → 勾选「保存 NFO 元数据」）

| 步骤 | 期望 |
|---|---|
| 用 **merge** 模式下一个视频 | 目录里多出 `同名.nfo` |
| 用文本编辑器打开 | 是合法 XML，有 `<title>` / `<plot>` / `<runtime>` |
| 丢进 Jellyfin 媒体库 | 能被刮削出条目（**关键**：若静默丢弃，说明 XML 有问题） |
| 切到 **音视频分离** 模式再下一次 | **不产生** NFO（这是刻意设计：两个产物都不完整） |

注意 `<runtime>` 不应出现 `0`（v1.4.13 修）。

### B2. 合集批量（v1.4.14 新增）

| 步骤 | 期望 |
|---|---|
| 打开一个**属于合集**的视频（如 BV1Wi4y1k7ed，7 集） | 弹窗出现「所属合集」区块，显示《合集名》与集数 |
| 勾选「下载整个合集」 | 底部「共 N 个任务」变成合集集数 |
| 开始下载 | 逐集建立任务并下载 |

**注意**：不是每个视频都有合集——没有时该区块不显示，这是正常的。

### B3. 章节（选项页 → 勾选「保存章节」）

找一个**进度条上有分段标记**的视频下载，应产出 `chapters.txt`（或 `.vtt`）。
若没有产出，可能是该视频确实无章节——**这一项的 `view_points` 真实字段结构尚未真机确认**。
